# Сервис портфолио студентов

Учебное веб-приложение на Django для систематизации, хранения и демонстрации академических результатов, исследовательских проектов, подтверждающих документов и призовых достижений студентов.

Проект разработан поэтапно в рамках единого репозитория:
1. **ПР1–ПР3**: Консольное объектно-ориентированное приложение, сущности предметной области, файловое хранилище JSON и набор тестов `pytest`.
2. **ПР5**: Переход к архитектуре Django: создание проекта и независимых приложений, двухуровневая маршрутизация URL, view-функции и обработка ошибки 404.
3. **ПР6**: Переход на систему шаблонов Django Template Language (DTL): базовый каркас `base.html`, наследование, включаемые компоненты `{% include %}`, пространства имён `app_name`, фильтры шаблонов и подключение статических файлов (CSS, JS, логотип).
4. **ПР7**: Реляционная база данных SQLite: проектирование схемы DDL со связями и внешними ключами, скрипт пакетного импорта данных из JSON, коллекция параметризованных SQL-запросов и интеграция выборки данных в веб-интерфейс Django через библиотеку `sqlite3`.

## 2. Предметная область и сущности

В проекте реализованы 4 взаимосвязанные сущности:

### Студент (`Student`)
* **Назначение:** базовый субъект системы портфолио.
* **Атрибуты:** `id` (уникальный идентификатор), `name` (ФИО), `gpa` (средний академический балл), `skills` (список освоенных навыков и технологий).
* **Методы:**
  * `calculate_rating(projects_count)` — расчёт суммарного рейтинга активности: `(gpa * 10) + (projects_count * 15)`.
  * `check_profile_completion()` — определение степени заполненности профиля по количеству навыков.
  * `from_data(dict)` — фабричный метод создания объекта из словаря JSON.

### Проект (`Project`)
* **Назначение:** учебная или научно-исследовательская работа студента.
* **Атрибуты:** `id` (идентификатор), `title` (название), `status` («В разработке», «Завершен», «Планируется»), `student` (ссылка на автора — объект `Student`).
* **Методы:**
  * `update_status(new_status)` — валидация и обновление жизненного цикла проекта.
  * `get_status_info()` — строковое описание статуса проекта.

### Документ (`Document`)
* **Назначение:** скан-копия диплома, сертификата или приказа.
* **Атрибуты:** `id` (идентификатор), `title` (наименование), `file_path` (путь к файлу документа), `owner` (студент-владелец — объект `Student`).
* **Свойства:**
  * `extension` — автоматическое извлечение расширения файла в нижнем регистре (например, `pdf`, `png`, `docx`).

### Достижение (`Achievement`)
* **Назначение:** награда, победа в олимпиаде или хакатоне.
* **Атрибуты:** `id` (идентификатор), `title` (наименование), `issue_date` (дата получения), `student` (ссылка на студента), `category` (категория: «IT», «Наука», «Спорт»), `document` (ссылка на подтверждающий объект `Document` или `None`).
* **Методы:**
  * `is_recent(year)` — проверка актуальности награды на указанный год.

## 3. Слой реляционной базы данных (SQLite и SQL — ПР7)

В рамках ПР7 организован слой реляционного хранения данных без применения Django ORM (модели ORM внедряются на последующих этапах).

### Структура таблиц базы данных (`data/portfolio.sqlite`)

| Таблица | Поле | Тип данных | Ограничения | Назначение |
|---|---|---|---|---|
| **`students`** | `id` | INTEGER | PRIMARY KEY | Идентификатор студента |
| | `name` | TEXT | NOT NULL | ФИО студента |
| | `gpa` | REAL | NOT NULL | Академический средний балл |
| | `skills` | TEXT | NOT NULL DEFAULT '' | Список навыков через запятую |
| **`projects`** | `id` | INTEGER | PRIMARY KEY | Идентификатор проекта |
| | `title` | TEXT | NOT NULL | Название проекта |
| | `status` | TEXT | NOT NULL | Статус работы |
| | `student_id` | INTEGER | NOT NULL, FOREIGN KEY → `students(id)` | Автор проекта |
| **`documents`** | `id` | INTEGER | PRIMARY KEY | Идентификатор документа |
| | `title` | TEXT | NOT NULL | Название документа/сертификата |
| | `file_path` | TEXT | NOT NULL | Путь к файлу на диске |
| | `student_id` | INTEGER | NOT NULL, FOREIGN KEY → `students(id)` | Студент-владелец |
| **`achievements`** | `id` | INTEGER | PRIMARY KEY | Идентификатор достижения |
| | `title` | TEXT | NOT NULL | Название достижения |
| | `issue_date` | TEXT | NOT NULL | Дата получения (`YYYY-MM-DD`) |
| | `student_id` | INTEGER | NOT NULL, FOREIGN KEY → `students(id)` | Награжденный студент |
| | `category` | TEXT | NOT NULL | Категория награды (IT, Наука, Спорт) |
| | `document_id` | INTEGER | NULL, FOREIGN KEY → `documents(id)` | Подтверждающий документ |

### Архитектура работы с БД

* **`sql/schema.sql`** — DDL-скрипт создания структуры таблиц с использованием конструкций `CREATE TABLE IF NOT EXISTS`, первичных ключей (`PRIMARY KEY`) и связей (`FOREIGN KEY ... REFERENCES`).
* **`db/database.py`** — модуль подключения. Функция `get_connection()` подключается к `data/portfolio.sqlite`, включает строгую ссылочную целостность командой `PRAGMA foreign_keys = ON` и настраивает фабрику строк `conn.row_factory = sqlite3.Row` для обращения к полям выборки по именам колонок.
* **`db/import_json.py`** — модуль миграции данных. Считывает `data/*.json` и переносит записи в SQLite пакетным методом `executemany()` с поддержкой транзакций (`commit` / `rollback`), соблюдая иерархию связей (сначала родительские таблицы `students` и `documents`, затем зависимые `projects` и `achievements`).
* **Безопасность SQL:** Все пользовательские параметры в представлениях передаются через параметризованные запросы с плейсхолдерами `?`, исключая SQL-инъекции.

### Коллекция SQL-запросов (`sql/queries.sql`)

В проекте реализовано 12 SQL-запросов (покрывают все типы операций, требуемые в ПР7):
1. **Выборка и сортировка:** список всех студентов с сортировкой по GPA (`SELECT ... ORDER BY gpa DESC`).
2. **Выборка и сортировка:** список всех проектов с сортировкой по названию (`SELECT ... ORDER BY title ASC`).
3. **Фильтрация WHERE:** отбор студентов-отличников (`WHERE gpa >= 4.5`).
4. **Фильтрация WHERE:** завершенные проекты (`WHERE status = 'Завершен'`).
5. **Соединение JOIN:** проекты с авторами-студентами (`JOIN students ON projects.student_id = students.id`).
6. **Соединение LEFT JOIN:** достижения со студентами и опциональными документами (`LEFT JOIN documents ON achievements.document_id = documents.id`).
7. **Агрегатные функции:** статистика по GPA (`COUNT(*)`, `AVG(gpa)`, `MIN(gpa)`, `MAX(gpa)`).
8. **Агрегатные функции:** подсчет проектов в разработке (`COUNT(*) ... WHERE status = 'В разработке'`).
9. **Группировка GROUP BY:** подсчет проектов по каждому студенту (`LEFT JOIN ... GROUP BY students.id`).
10. **Группировка GROUP BY:** подсчет наград по категориям (`GROUP BY category`).
11. **Фильтрация групп HAVING:** студенты с двумя и более проектами (`GROUP BY ... HAVING COUNT(projects.id) >= 2`).
12. **Подзапрос NOT IN:** поиск студентов, у которых еще нет ни одного проекта (`WHERE id NOT IN (SELECT DISTINCT student_id FROM projects)`).

## 4. Веб-интерфейс и архитектура шаблонов (ПР5–ПР6)

Веб-часть полностью переведена на архитектуру Django Template Language (DTL). Генерация HTML-строк в Python-коде (`page()`) устранена.

### Структура шаблонов

* **`templates/base.html`** — базовый шаблон проекта:
  * теги `DOCTYPE`, кодировка UTF-8, метатег `viewport`;
  * подключение Bootstrap 5.3 (CDN);
  * подключение собственного CSS `{% static 'homepage/css/style.css' %}`;
  * включение общей навигационной панели через `{% include "includes/navigation.html" %}`;
  * блоки `{% block title %}` и `{% block content %}`;
  * подвал с динамическим годом через JavaScript;
  * подключение скрипта `{% static 'homepage/js/main.js' %}`.
* **`templates/includes/navigation.html`** — компонент навигации с динамическими ссылками `{% url %}`.
* **`templates/404.html`** — пользовательская страница ошибки 404, обрабатываемая через `handler404`.
* **Включаемые шаблоны компонентов:**
  * `students/templates/students/includes/student_card.html` — карточка студента в списке.
  * `projects/templates/projects/includes/project_status.html` — цветной бейдж статуса проекта.

### Маршруты и пространства имён (Namespaces)

Каждое приложение изолировано в собственном пространстве имён:

| URL-шаблон | Имя маршрута | View-функция | Описание страницы |
|---|---|---|---|
| `/` | `homepage:index` | `homepage.views.index` | Главная страница и навигация к разделам |
| `/statistics/` | `homepage:statistics` | `homepage.views.statistics` | Сводная аналитика (агрегаты, группировки) |
| `/students/` | `students:list` | `students.views.students_list` | Реестр студентов с сортировкой по GPA |
| `/students/<int:student_id>/` | `students:detail` | `students.views.student_detail` | Профиль студента, проекты, награды, расчет рейтинга |
| `/students/search/` | `students:search` | `students.views.student_search` | Параметризованный поиск по минимальному GPA |
| `/projects/` | `projects:list` | `projects.views.projects_list` | Список проектов со статусами и авторами |
| `/projects/<int:project_id>/` | `projects:detail` | `projects.views.project_detail` | Детальная карточка проекта со ссылкой на автора |
| `/achievements/` | `achievements:list` | `achievements.views.achievements_list` | Список наград с бейджами подтверждения |
| `/achievements/<int:achievement_id>/` | `achievements:detail` | `achievements.views.achievement_detail` | Карточка достижения с информацией о документе |

При обращении к несуществующему объекту (`<id>`) или неверному адресу возвращается страница 404 с кодом статуса HTTP 404.

## 7. Развертывание и запуск приложения

### 1. Подготовка виртуального окружения
```bash
# Создание виртуального окружения
python -m venv venv

# Активация окружения:
# Git Bash / Linux / macOS:
source venv/Scripts/activate

# Windows PowerShell:
.\venv\Scripts\Activate.ps1

# Windows CMD:
venv\Scripts\activate.bat

# Установка зависимостей
pip install -r requirements.txt
```

### 2. Инициализация базы данных и импорт данных
Скрипт создает структуру таблиц из `sql/schema.sql` и загружает исходные данные из `data/*.json`:
```bash
python -m db.import_json
```
*(Ожидаемый вывод: `База данных успешно создана и наполнена из JSON-файлов.`)*

### 3. Запуск веб-сервера разработки Django
```bash
python manage.py runserver
```
Веб-интерфейс доступен в браузере по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/).

### 4. Запуск консольной версии (сохранена с ПР3)
```bash
python main.py
```
